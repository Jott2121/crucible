# crucible (ai-agentic-code-testing)

Mutation-testing tool that answers "your AI wrote the tests, who tested the tests?" — injects real defects into a module and measures how many its own test suite actually kills, then runs a harden loop where a Critic writes tests against named survivors.

- **Status:** active, public repo with CI/CodeQL. Ships **three** things: the PyPI package `crucible-harden`, the GitHub Action, and a Claude Code plugin. Live experiment receipts in `experiments/`.
- **Install:** `pip install crucible-harden` (the command it installs is `crucible`), or `uvx --from crucible-harden crucible score ...` with no install.
- **Entry points:** `src/` (the tool), `skills/harden-tests/SKILL.md` (the operator ritual, shipped as the plugin), `.claude-plugin/` (plugin + marketplace manifests), `action.yml` (GitHub Action), `docs/MUTATION.md`, `experiments/RESULTS-B.md`
- **Agent setup:** `.claude/settings.json` — allowlists the test/build/lint/read-only-git commands, forces an `ask` before editing `publish.yml` or `action.yml` (the release trap surface), and runs `.claude/hooks/ruff-check.sh` on every `Edit`/`Write` to a `.py` file under `src/` or `tests/`. Repo-local, does **not** ship in the plugin (that is `skills/` + `.claude-plugin/`).
- **Run/test:** `pip install -e ".[dev]" && python -m pytest -q` (443 tests). Lint gate is `ruff check src tests` (config in `pyproject.toml`, narrow on purpose, also a CI step). Also usable via `uses: Jott2121/crucible@v1` in a workflow.
- **RELEASE CONVENTION (easy to get wrong):** this repo has **two version lines**. PyPI package releases must be tagged **`pypi-v<version>`** — `publish.yml` is gated on that prefix and the build asserts the tag matches `pyproject.toml`. GitHub Action releases stay `v1.x`. A package release tagged `v0.1.2` will silently do nothing. **Cut releases with the `/release` skill (`.claude/skills/release/SKILL.md`)** — it mechanizes both lines and, critically, verifies the publish run actually fired (the trigger is a published GitHub *Release*, not a pushed tag).
- **Constraints:** mutation kills must be earned — the harden loop discards Critic-written tests that fail on pristine code rather than banking an unearned kill; only run on-command per Jeff (not autonomous). `tests/test_packaging.py` guards the metadata PyPI validates but `twine check` does not (classifiers, direct-URL deps) plus the floor nothing validates (CI must run the lowest Python `requires-python` claims).
